# LLM Browser Agent

Chrome-расширение (Manifest V3), через которое языковая модель управляет браузером как человек: читает страницу, кликает, вводит текст, прокручивает и переходит по ссылкам, пока не выполнит задачу.

Модель работает на вашем сервере в локальной сети (llama.cpp, Ollama) или в облаке по API-ключу (Google Gemini, любой OpenAI-совместимый сервис). Облако по умолчанию не используется.

- **Восприятие текстом.** Страница превращается в компактный список элементов с номерами (`[12] button "Войти"`) и видимый текст. Понимает shadow DOM, iframe с других сайтов и редакторы кода (CodeMirror, Monaco, Ace).
- **Настоящие клики и ввод** через `chrome.debugger` (CDP) с плавным движением мыши. Если отладчик недоступен, используются DOM-события.
- **Безопасность.** Оплату, удаление, отправку и ввод паролей определяет расширение, а не модель. Перед такими действиями оно спрашивает подтверждение. Текст страниц модель получает как данные, не как инструкции.
- **Ночной режим.** Агент работает без вас: рискованное откладывается в очередь на утро, после перезапуска браузера задача продолжается сама.
- **Скриншоты с номерами элементов** для моделей со зрением: на заминках или на каждом шаге.
- **Сценарии**: удачный запуск сохраняется и повторяется без модели; если сайт изменился, задача передаётся нейросети.
- **Telegram**: запросы подтверждения с кнопками, ответы на вопросы агента и итог задачи прямо в чате.
- **Журнал** каждого шага в IndexedDB с экспортом в JSON.

## Установка

### Готовая сборка

1. Скачайте `llm-browser-agent-*-chrome.zip` со страницы [Releases](https://github.com/yapimiu/llm_chrome/releases/latest).
2. Распакуйте в постоянную папку — Chrome грузит расширение прямо из неё, удалять её нельзя.
3. Откройте `chrome://extensions`, включите **«Режим разработчика»**, нажмите **«Загрузить распакованное расширение»** и выберите распакованную папку.
4. Дальше — как в шагах 4–5 ниже.

Обновление: скачайте новый zip, распакуйте поверх той же папки и нажмите ↻ у расширения.

### Сборка из исходников

Нужен Node.js 20 или новее.

```bash
git clone https://github.com/yapimiu/llm_chrome.git
cd llm_chrome
npm install
npm run build
```

Сборка появится в `dist/chrome-mv3`.

1. Откройте `chrome://extensions`.
2. Включите **«Режим разработчика»** (переключатель справа вверху).
3. Нажмите **«Загрузить распакованное расширение»** и выберите папку `dist/chrome-mv3`.
4. Откроется страница настроек. Впишите адрес сервера и модель, нажмите **«Проверить соединение»**, затем **«Сохранить»**.
5. Клик по иконке расширения открывает боковую панель агента.

**Обновление:** `git pull && npm install && npm run build`, затем кнопка ↻ у расширения в `chrome://extensions`.

## Сервер с моделью

Расширение говорит с моделью по OpenAI-совместимому протоколу (`/v1/chat/completions` со стримингом). Сервер может стоять на другой машине в той же сети.

Модели, на которых проверялось:

| Режим | Модель | Где |
|---|---|---|
| Быстрый | Qwen3-14B, gpt-oss-20b | целиком на GPU |
| Ночной | Qwen3-32B | частичная выгрузка в RAM, ответ может идти минуты |

### llama.cpp (`llama-server`)

```bash
llama-server \
  -m /models/Qwen3-14B-Q4_K_M.gguf \
  --host 0.0.0.0 --port 8080 \
  -c 16384 \
  -ngl 99 \
  --jinja \
  --api-key "длинный-случайный-ключ"
```

- `--host 0.0.0.0` — слушать сеть, а не только localhost.
- `-c` — контекст. Он должен быть не меньше «Бюджета контекста» в настройках профиля.
- `--jinja` — нужен, чтобы работал переключатель рассуждений Qwen3 (`enable_thinking`).
- `--api-key` — тот же ключ впишите в профиль в настройках расширения.
- Для 32B на ночь уменьшите `-ngl` до числа слоёв, которые влезают в видеопамять. Остальные слои уйдут в RAM.

### Ollama

Ollama по умолчанию слушает только localhost и отклоняет запросы от расширений. Добавьте переменные окружения:

```bash
sudo systemctl edit ollama.service
```

```ini
[Service]
Environment="OLLAMA_HOST=0.0.0.0"
Environment="OLLAMA_ORIGINS=chrome-extension://*"
Environment="OLLAMA_CONTEXT_LENGTH=16384"
```

```bash
sudo systemctl restart ollama
ollama pull qwen3:14b
```

- `OLLAMA_ORIGINS=chrome-extension://*` — без этого будет ошибка 403.
- `OLLAMA_CONTEXT_LENGTH` — через `/v1` Ollama не принимает размер контекста в запросе и **молча обрезает** длинный промпт. Проверка связи в настройках покажет реальный контекст и предупредит о расхождении.
- В адрес сервера впишите `http://IP-сервера:11434`.

### Закройте порт файрволом

У Ollama нет API-ключа, а у llama-server ключ передаётся открытым текстом по HTTP. Пустите к порту только вашу домашнюю сеть:

```bash
# пример для ufw и сети 192.168.0.0/24; порт 8080 — llama-server, 11434 — Ollama
sudo ufw allow from 192.168.0.0/24 to any port 8080 proto tcp
sudo ufw deny 8080/tcp
sudo ufw enable
```

Проверка с машины, где стоит браузер:

```bash
curl -H "Authorization: Bearer длинный-случайный-ключ" http://192.168.0.3:8080/v1/models
```

## Облачные модели по ключу

В настройках у профиля есть поле **«Провайдер»**. Профиль **«Облако»** уже настроен на Google Gemini. «Быстрый» и «Ночной» остаются локальными.

**Google Gemini**
1. Возьмите ключ в [Google AI Studio](https://aistudio.google.com/apikey).
2. Настройки → вкладка «Облако» → вставьте ключ → «Проверить соединение» → выберите модель → «Сохранить».

**Любой OpenAI-совместимый сервис** (OpenRouter, свой прокси и т.п.)
1. Провайдер: «OpenAI-совместимый API».
2. Адрес вставьте как в документации сервиса, вместе с версией: `https://example.com/v1`.
3. Вставьте ключ.

Проверка связи показывает адрес, по которому реально пойдут запросы.

> ⚠️ С облачной моделью текст каждой страницы, по которой ходит агент, уходит на чужой сервер. Для личных кабинетов лучше держать модель в своей сети. Для внешних адресов в настройках показывается предупреждение.

Если сервис перегружен (`503 high demand`, `429`), агент сам повторяет запрос с растущей паузой: до 3 раз внутри шага, затем ждёт до 2 минут между шагами. Сдаётся только после 8 неудач подряд.

## Как пользоваться

1. Откройте сайт, где нужно что-то сделать.
2. Откройте панель агента (иконка расширения).
3. Впишите задачу и нажмите **«Старт»**.

В ленте шагов видно, что модель решила и что из этого вышло. **«Что видела модель и что ответила»** раскрывает полный промпт и сырой ответ. **Пауза** вступает в силу между действиями, **Стоп** обрывает и запрос к модели.

**«Что видит модель»** (внизу панели):
- **Показать** — снимок страницы ровно в том виде, в каком он уйдёт в промпт. **Подсветка** рисует номера прямо на странице.
- **Почему не виден?** — кликните элемент, и панель объяснит, почему модель его не видит: перекрыт, невидим, не влез в лимит, скрыт заметкой.
- **Скрыть элемент…** — кликните элемент, и модель перестанет его видеть на этом сайте. Для кнопок с текстом правило — текст, для иконок — CSS-селектор.
- **Это кнопка «Далее»…** — кликните кнопку перехода к следующему уроку или странице. Модель будет видеть её как `[12] button "🔬🧪" ← NEXT` на всех страницах сайта, даже если текст на ней каждый раз другой (шутки, одни эмодзи).

**⏩ Пролистать курс** — режим без модели для курсов, где содержимое можно не читать, а только жать «дальше». Агент прокручивает страницу в самый низ и жмёт нижнюю кнопку (или отмеченную как «Далее»). Если ничего не изменилось, повторяет ещё два раза, затем жмёт кнопки снизу вверх и после каждой снова возвращается вниз. На шаг уходят доли секунды, модель не вызывается. Кнопки, приклеенные к экрану (боковое меню, кнопка чата, всплывающие окна), и кнопки внутри тренажёров-iframe жмутся в последнюю очередь, даже если они ниже кнопки урока; исключение — приклеенная кнопка «Дальше»/«Далее».

Если пролистывание застряло (на странице не осталось кнопок, все перебраны или кнопки гоняют страницу по кругу), а в панели включено «Застрял — звать нейросеть, потом листать дальше», страница передаётся модели. Она получает задачу «убери заминку»: решить задание, закрыть окно, заполнить поле. Как только курс сдвинулся (открылась другая страница или модель вызвала `done`), пролистывание продолжается само. Если модель ответила `НЕ_МОГУ` или дважды «помогла» на одной странице без продвижения, всё останавливается со звуковым сигналом. Шагов на одну заминку — не больше `skipAgentSteps` (по умолчанию 25).

В заметке сайта галочка «Скрыть иконки без подписи на приклеенных панелях и в тренажёрах» (строка `@иконки` в поле «Скрыть от модели») убирает кнопки-значки без текста — чат, переключатель темы, «избранное», значки бокового меню — и у модели, и у пролистывания. Иконки в самом уроке и кнопки с текстом остаются.
- Не жмёт: неактивные кнопки, поля ввода и редакторы кода, ссылки на другие сайты, рискованное (оплата, удаление, отправка), «Сбросить», «Выйти», «Оценить», а также всё, что скрыто заметкой сайта.
- Останавливается, если ушёл на другой сайт, если перебрал все кнопки без толку или по кнопке «Остановить».

**Профили.** «Быстрый», «Ночной» и «Облако» переключаются в выпадающем списке сверху панели. У каждого свои сервер, модель, температура, лимиты и режим рассуждений.

**Системный промпт** лежит в [`src/prompts/system.md`](src/prompts/system.md). После правки выполните `npm run build` и перезагрузите расширение.

### Скриншоты

Модель по умолчанию читает страницу текстом. Если она умеет видеть картинки (Gemini, Qwen2.5-VL, Gemma 3, llava; у llama-server нужен `--mmproj`), включите в профиле «Модель видит картинки» и выберите в разделе «Агент» режим «Скриншоты»:
- **когда агент застрял** (по умолчанию) — прошлый шаг не удался, ничего не изменил или сработал детектор зацикливания;
- **на каждом шаге**.

К тексту прикладывается снимок видимой части страницы, где каждый элемент обведён рамкой со своим номером `[N]`. Так модель понимает иконки без подписей, картинки и раскладку. Кнопка «Скриншот» в блоке «Что видит модель» показывает именно эту картинку, а в ленте шагов она видна в «Что видела модель». Скриншот ~1000 токенов, ширина до 1280 px.

### Действия агента

Кроме кликов, ввода, выбора, прокрутки и переходов модель может:
- `hover` — навести мышь (выпадающие меню, подсказки);
- `press_key` — Escape, Tab, Shift+Tab, стрелки, PageUp/PageDown, Home/End. Enter и пробел намеренно недоступны: это клик или отправка формы, и они проходят проверку риска как `click` и `type`;
- `drag` — перетащить элемент на другой (канбан, сортировка, загрузка файлов на зону). Нужен CDP; обе точки должны быть на экране;
- `wait_for` — дождаться текста на странице (до 30 с) вместо паузы наугад;
- `scroll` с `index` — прокрутить блок с этим элементом (список, чат, боковую панель), а не всю страницу.

### Сценарии: запись и повтор

Под результатом удачного запуска есть кнопка **«💾 Сохранить как сценарий»**. Сценарий хранит действия с описаниями элементов (`button "Войти"`), а не их номера. В блоке **«Сценарии»** кнопка **▶ Повторить** выполняет его без модели, за секунды.
- Элемент ищется по точному описанию, затем без изменчивых частей (значение поля, `disabled`), затем по тегу и имени; среди одинаковых берётся тот же по счёту.
- Рискованные шаги (оплата, удаление, отправка) при повторе снова требуют подтверждения.
- Пароли и номера карт в сценарий не записываются: при повторе их спросят.
- Если сайт изменился и элемента нет, повтор останавливается. Кнопка **«🧠 Передать нейросети»** запускает агента с исходной задачей с текущего места.

### Уведомления в Telegram

Настройки → «Уведомления в Telegram»:
1. Создайте бота у [@BotFather](https://t.me/BotFather) командой `/newbot` и вставьте токен.
2. Напишите своему боту любое сообщение и нажмите «Найти chat id».
3. «Отправить тест» → «Включить» → «Сохранить».

Что приходит: запрос подтверждения рискованного действия с кнопками **✅ Выполнить / ❌ Отклонить**, вопросы агента (ответьте реплаем) и итог задачи. Ответ из чата равносилен нажатию в панели. Если ответили в панели, сообщение в чате помечается «Отвечено в браузере». Ответы принимаются только из указанного чата. Ночью это значит, что рискованное действие можно подтвердить с телефона, а не ждать утра.

### Ввод текста

По умолчанию текст вставляется в поле целиком (`Input.insertText`): быстро и надёжно. Галочка «Вводить текст по буквам» в настройках агента включает ввод по одному символу: на каждую букву страница получает `keydown → input → keyup`, между буквами пауза «Пауза между буквами» (по умолчанию 30 мс). Это нужно полям, которые реагируют на каждое нажатие: подсказки при вводе, маски телефона и даты, счётчики символов. Работает только с CDP (галочка «Клики через chrome.debugger»); в редакторы кода текст всё равно вставляется целиком — иначе редактор сам закрывал бы скобки и расставлял отступы поверх вставленного кода.

## Безопасность и ночной режим

**Что считается рискованным.** Решает расширение, а не модель: модель видит текст страницы, и страница может её уговорить.

| Что | Как определяется |
|---|---|
| Оплата | кнопки «оплатить», «купить», «оформить заказ», `pay`, `checkout`…; любые действия на адресах с `checkout`, `payment`, `pay`, `billing` |
| Удаление | «удалить», «очистить», `delete`, `remove`… |
| Отправка | «отправить», «опубликовать», `send`, `post`, `submit`…; Enter в поле сообщения (кроме поиска) |
| Пароль, карта | ввод в такое поле, отправка формы с ним |

Словари правятся в настройках, раздел «Безопасность». Модель может сама пометить шаг как `"risky": true`, но снять подтверждение она не может.

**Обычный режим.** Перед рискованным шагом агент ждёт **«Выполнить / Отклонить»**. В карточке видно, какое действие рискованное и почему. Остальные шаги идут без остановок. «Подтверждать каждый шаг» — отладочный режим, по умолчанию выключен.

**Автономный (ночной) режим.** Включается галочкой в панели.
- **Рискованное действие.** Звучит сигнал, показывается системное уведомление, агент ждёт подтверждения N секунд (по умолчанию 120). Если никто не ответил, действие уходит в **очередь на утро**, а агент делает остальную часть задачи.
- **Утром.** В панели «Очередь на утро» → **«Продолжить отсюда»**: открывается та страница, и начинается обычный запуск с контекстом ночной задачи.
- **Вопросы.** На `ask_user` модель отвечает себе сама и указывает допущение в результате.
- **Перезапуск.** Если браузер или расширение перезапустились, ночная задача продолжается сама. Днём в панели появится «Задача прервана: Продолжить / Отменить».

**Защита от зацикливания:**
- одно и то же действие на неизменной странице — предупреждение модели на 3-м повторе, остановка на 6-м;
- если модель несколько шагов подряд топчется на месте (действия не удаются или ничего не меняют), агент сам прокручивает страницу вниз и говорит ей об этом.

## Заметки для сайтов

Настройки → «Заметки для сайтов». Шаблон — домен (с поддоменами) и, при желании, начало пути: `practicum.yandex.ru/learn`.

- **Заметка** — подсказка модели, попадает в самый конец промпта. Её модель слушается сильнее всего.
- **Скрыть от модели** — по одному правилу на строку: текст кнопки или `css: селектор`. Проще добавлять кнопкой «Скрыть элемент…» в панели.
- **Кнопка «Далее»** — `css: селектор` или текст. Такая кнопка получает в наблюдении пометку `← NEXT`, и модель жмёт её, когда на странице больше нечего делать. Проще отмечать кнопкой «Это кнопка „Далее“…» в панели.
- **Рискованные действия на этом сайте** — «спрашивать», «выполнять без подтверждения» или «запрещать».
- **Не спрашивать подтверждения для** — тексты кнопок-исключений, например «Отправить ответ» на учебной платформе.

Пример заметки для Яндекс Практикума:

```
- Внизу каждого урока есть кнопка перехода к следующему уроку. Её текст шуточный и каждый раз разный («Уф, надеюсь, это всё?», «Погнали дальше»). Это кнопка «Далее».
- Если есть задание — выполни его один раз и нажми «Проверить». Если «Проверить» неактивна или задание уже засчитано — прокрути вниз и нажми «Далее».
- Не перечитывай урок и не вводи код повторно.
```


Чем конкретнее задача и чем явнее в ней сказано, когда остановиться, тем реже модель блуждает. Маленьким моделям (14B) сильно помогают заметки для сайтов.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| `403` при проверке связи (Ollama) | `OLLAMA_ORIGINS=chrome-extension://*` и перезапуск Ollama |
| `401` | API-ключ в профиле совпадает с `--api-key` сервера |
| `404` | адрес сервера и имя модели; проверка связи показывает реальный адрес запроса |
| «Сервер недоступен» | сервер слушает `0.0.0.0`, порт открыт для вашей сети |
| Предупреждение о контексте | `-c` у llama-server или `OLLAMA_CONTEXT_LENGTH` меньше бюджета в профиле — промпт будет обрезан |
| `503` / `429` в облаке | сервис перегружен; агент повторит сам. Если часто — возьмите модель полегче или переключитесь на локальный профиль |
| Модель ходит по кругу | заметка для сайта; «Скрыть элемент…» для отвлекающих кнопок; модель покрупнее или включённые рассуждения |
| Модель не видит кнопку | «Почему не виден?» в панели |
| Плашка «…отлаживает этот браузер» | так работает `chrome.debugger`. Если её закрыть, агент перейдёт на DOM-события |

## Разработка

Подробная инструкция по отладке — [DEBUGGING.md](DEBUGGING.md).

```bash
npm run chrome:install  # Chrome for Testing для dev-режима и e2e (один раз)
npm run mock-llm        # мок модели и тестовые страницы на 127.0.0.1:18080
npm run dev             # WXT с автоперезагрузкой в Chrome for Testing
npm run build           # сборка в dist/chrome-mv3
npm test                # юнит-тесты (Vitest)
npm run e2e             # e2e: настоящий Chrome + расширение + мок модели
npm run compile         # проверка типов
npm run zip             # zip для релиза в dist/
```

**Релиз.** Поднимите `version` в `package.json` и запушьте тег — GitHub Actions ([release.yml](.github/workflows/release.yml)) прогонит тесты, соберёт zip и выложит его в Releases:

```bash
git tag v0.1.0 && git push origin v0.1.0
```

Стек: TypeScript (строгий), [WXT](https://wxt.dev), Preact для панели и настроек, Vitest + jsdom.

```
src/
  entrypoints/
    background.ts      — цикл агента, CDP-сессии, журнал, очередь, восстановление после перезапуска
    content.ts         — сборщик страницы, подсветка, курсор, фреймы, действия в странице
    sidepanel/         — панель агента
    options/           — настройки
    offscreen/         — звуковой сигнал (service worker сам звук не играет)
  lib/
    agent/             — цикл, действия, парсер ответа, промпт, история, риск, очередь, застревание, сценарии
    dom/               — сборщик и сериализатор страницы, исполнитель, правила скрытия
    exec/              — CDP-драйвер
    llm/               — клиент со стримингом, провайдеры, проверка связи
    notify/            — Telegram: уведомления, кнопки подтверждения, ответы
    log/               — журнал IndexedDB
    screenshot.ts      — скриншот с номерами элементов
  prompts/system.md    — системный промпт агента
tests/                 — юнит-тесты
e2e/                   — мок модели, тестовые страницы, e2e в настоящем Chrome
```

Как устроен агент и какие решения принимались по ходу, подробно описано в [report.md](report.md).
