# Отладка и работа с проектом

Как запустить расширение в режиме разработки, где смотреть логи, как гонять агента без настоящей модели и как разбирать типичные поломки.

---

## 1. Запуск за три команды

Нужен Node.js 20+.

```bash
npm install
npm run chrome:install     # Chrome for Testing в .cache/chrome (один раз, ~200 МБ)
```

Дальше два терминала:

```bash
npm run mock-llm           # терминал 1: мок модели + тестовые страницы на http://127.0.0.1:18080
```

```bash
npm run dev                # терминал 2: сборка с автоперезагрузкой + Chrome for Testing с расширением
```

`npm run dev` открывает отдельный Chrome for Testing с уже загруженным расширением и страницей со списком тестовых страниц. Профиль браузера лежит в `.cache/dev-profile` и сохраняется между запусками: настройки, журнал и сценарии не пропадают.

> Обычный Google Chrome (с версии 137) не загружает расширения флагом `--load-extension`, поэтому для dev-режима и e2e нужен Chrome for Testing. Путь к нему задан в `web-ext.config.ts` (файл локальный, в git не попадает). На Linux и Windows поправьте путь в нём.

**Подключить модель.** В открывшемся браузере: иконка расширения → «Настройки» → профиль «Быстрый»:
- без модели: адрес `http://127.0.0.1:18080`, модель `mock`;
- с настоящей моделью: адрес вашего llama-server / Ollama / облака (см. README).

**Правки кода** подхватываются сами: WXT пересобирает и перезагружает расширение. Открытые страницы при этом теряют content script — он внедрится заново на следующем шаге. Правка `src/prompts/system.md` тоже подхватывается автоматически.

## 2. Как устроено (карта для отладки)

```
Боковая панель (sidepanel/)          Настройки (options/)
        │  bg:* сообщения                    │
        ▼                                    ▼
background.ts — service worker: цикл агента (AgentRunner), CDP, журнал,
                очередь на утро, пролистывание, сценарии, Telegram
        │  content:* сообщения (в каждый фрейм)         │ fetch
        ▼                                               ▼
content.ts — сборщик страницы, подсветка,          LLM-сервер (/v1/chat/completions)
             DOM-действия, ожидание текста          api.telegram.org
```

Один шаг агента (`src/lib/agent/runner.ts → step()`):
1. `observe` — `perception.ts` внедряет content script во все фреймы и собирает текст страницы; если нужен скриншот, рисует рамки с номерами и снимает экран (`screenshot.ts`).
2. `runStep` (`step.ts`) — промпт (`prompt.ts`), запрос к модели (`llm/client.ts`), разбор ответа (`parse.ts`).
3. Риск (`risk.ts`) → подтверждение в панели или в Telegram → `executeAction` (`tab-actions.ts`): CDP (`exec/cdp.ts`) или DOM-события в странице (`dom/act.ts`).

Префиксы сообщений: `bg:*` — UI → background, `ui:*` — background → UI, `content:*` — background → страница. Все типы — в `src/lib/messages.ts`.

## 3. Где смотреть логи и ставить точки останова

| Что | Как открыть DevTools | Что там |
|---|---|---|
| **Service worker** (`background.ts`) | `chrome://extensions` → карточка расширения → «Инспектировать: service worker» | цикл агента, CDP, Telegram, ошибки `recover failed`, `telegram failed`, `screenshot failed` |
| **Боковая панель** | правый клик внутри панели → «Просмотреть код» | UI, сообщения `ui:*` |
| **Настройки** | правый клик на странице настроек → «Просмотреть код» | форма настроек, проверка связи |
| **Content script** | DevTools обычной страницы → Console → в списке контекстов выбрать «LLM Browser Agent» | сборщик, DOM-действия, подсветка |
| **Журнал (IndexedDB)** | DevTools service worker → Application → IndexedDB | запуски и шаги целиком: наблюдение, ответы модели, скриншоты |
| **Настройки и сценарии** | DevTools service worker → Application → Extension storage → Local | `settings`, `macros`, `activeRun` (чекпоинт) |

**Точки останова.** Dev-сборка идёт с source maps: в DevTools → Sources ищите исходники по пути `src/...` (Cmd+P). Можно временно вписать `debugger;` в код — сработает при открытых DevTools нужного контекста.

**Service worker засыпает** через 30 секунд простоя, вместе с ним пропадает консоль. Во время запуска агента его держит «пульс» (`keepalive.ts`). Чтобы смотреть логи без запуска, держите DevTools service worker открытыми — пока они открыты, воркер не выгружается.

## 4. Инструменты отладки в самом расширении

**«Что видит модель»** (низ боковой панели):
- **Показать** — текст страницы ровно в том виде, в каком он уйдёт в промпт, плюс статистика: сколько элементов не влезло, сколько перекрыто или скрыто.
- **Подсветка на странице** — рамки с номерами прямо на странице.
- **Скриншот** — картинка с номерами, которую получит модель со зрением.
- **Почему не виден?** — кликните элемент, и панель скажет, каким правилом сборщик его отбросил.
- **Скрыть элемент…** и **Это кнопка «Далее»…** — правила для заметки сайта.

**Лента шагов.** У каждого шага есть «Что видела модель и что ответила»: история, заметки сайта, скриншот, полный текст страницы и сырой ответ модели (все попытки, с ошибкой разбора).

**Журнал запусков** (внизу панели) — прошлые запуски и экспорт в JSON. Его удобно прикладывать к баг-репорту.

**Пошаговый режим** — галочка «Подтверждать каждый шаг»: агент ждёт «Выполнить» перед каждым действием. Можно посмотреть на решение модели до того, как оно выполнится.

**Удалённый лог** — «Настройки → Логирование»: каждый шаг уходит POST-запросом на ваш URL.

## 5. Мок модели и тестовые страницы

`npm run mock-llm` поднимает на `http://127.0.0.1:18080`:
- `/v1/chat/completions` — «модель», которая отвечает по сценарию;
- тестовые страницы (список на `/`): маска телефона, форма с Enter, масштаб, новая вкладка, iframe, shadow DOM, меню по наведению, модальное окно, перетаскивание, долгая загрузка, прокручиваемый блок, форма для сценария.

Сценарий выбирается меткой в задаче. Откройте страницу `/hover`, в задаче напишите `[hover] открой настройки` и нажмите «Старт» — мок наведёт мышь на меню и кликнет «Настройки». Метки и ответы задаются в `e2e/server.mjs`, объект `scenarios`. Чтобы добавить свою проверку, добавьте страницу в `pages` и функцию в `scenarios`: она получает текст страницы и номер запроса и возвращает JSON-ответ модели.

`E2E_SHOT_DIR=/tmp/shots npm run mock-llm` сохраняет каждый скриншот, полученный «моделью», в эту папку.

## 6. Тесты

```bash
npm test                 # юнит-тесты (Vitest + jsdom), ~1 с
npm run test:watch       # то же в режиме наблюдения
npm run compile          # проверка типов
npm run e2e              # сборка + настоящий Chrome с расширением + мок модели
npm run e2e -- drag,hover  # только выбранные сценарии
HEADLESS=1 npm run e2e   # без окна
```

E2E проверяет всю цепочку: маску ввода, подтверждение при Enter в форме, детектор зацикливания, клики при масштабе 150%, новую вкладку, iframe с другого сайта, shadow DOM, наведение, Escape, перетаскивание, `wait_for`, прокрутку блока, доставку скриншота модели, запись сценария и повтор без модели. При падении выводятся все шаги агента с результатами.

## 7. Типичные проблемы

| Симптом | Где искать |
|---|---|
| Клик «успешен», но ничего не произошло | «Подсветка» — совпадает ли рамка с кнопкой. Проверьте масштаб страницы (Cmd+0). Сайт может требовать настоящих событий: включите «Клики через chrome.debugger». |
| Модель не видит кнопку | «Почему не виден?» в панели. Если «не влез в лимит» — увеличьте «Лимит наблюдения». |
| Ввод «не попал в поле» | Лента шага → сообщение с тем, что сейчас в поле. Для масок и подсказок — «Вводить текст по буквам». |
| Ходит по кругу | Лента: предупреждения `LOOP`, заметки `AUTO-SCROLL`. Помогают заметка для сайта, «Скрыть элемент…» и скриншоты (если модель со зрением). |
| Скриншота нет в шаге | Профиль → «Модель видит картинки»; «Агент → Скриншоты» не «никогда». Вкладка агента должна быть активной, а окно — не свёрнутым. В консоли service worker смотрите `screenshot failed`. |
| Модель ругается на картинку (400) | Модель или сервер без зрения: у llama-server нужен `--mmproj`. Выключите «Модель видит картинки». |
| Telegram молчит | «Настройки → Telegram → Отправить тест». `401` — неверный токен; «чат не найден» — сначала напишите боту `/start`. |
| Кнопки в Telegram не реагируют | Этого бота опрашивает кто-то ещё (другой скрипт или webhook). Нужен отдельный бот только для агента; webhook снимается запросом `https://api.telegram.org/bot<токен>/deleteWebhook`. |
| Повтор сценария «нет элемента» | Сайт поменял текст или вёрстку. «🧠 Передать нейросети» продолжит с этого места, после удачного запуска сохраните сценарий заново. |
| Жёлтая плашка «…отлаживает этот браузер» | Так работает CDP. Если её закрыть, агент до конца запуска перейдёт на DOM-события. |
| После правки ничего не поменялось | В dev-режиме смотрите вывод `npm run dev`. Со сборкой из `dist/` нажмите ↻ в `chrome://extensions`. |

## 8. Где что лежит (новые функции)

| Функция | Файлы |
|---|---|
| Действия `hover`, `press_key`, `drag`, `wait_for`, прокрутка блока | `lib/agent/actions.ts` (типы, схема), `parse.ts` (разбор), `dom/act.ts` (DOM-фолбэк), `exec/cdp.ts` (мышь и клавиши), `tab-actions.ts` (маршрутизация) |
| Скриншоты с номерами | `lib/screenshot.ts`, `background.ts → observeAgentTab`, `runner.ts → needsScreenshot`, `prompt.ts` (картинка в сообщении) |
| Запись и повтор | `lib/agent/macro.ts` (запись, поиск элемента, `Replayer`), `macro-store.ts`, `sidepanel/Macros.tsx` |
| Telegram | `lib/notify/telegram.ts` (клиент и ожидание ответов), `notify/format.ts` (тексты), `background.ts → telegramSync` |
| E2E и мок модели | `e2e/server.mjs`, `e2e/run.mjs` |
